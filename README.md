# NOVA ERP

Интерактивный MVP корпоративного портала для e-commerce компании FORM & HOME. React + TypeScript + Vite, Tailwind CSS, компоненты shadcn/ui на Radix, Lucide, Recharts, Zustand, React Hook Form и Zod. Шрифты Inter и Manrope поставляются локально.

## Запуск

Требуется Node.js 24 и npm.

```sh
npm ci
npm run dev
```

Откройте адрес из терминала, обычно `http://localhost:5173/`. Для доступа только с текущего компьютера: `npm run dev -- --host 127.0.0.1`.

**Демо-аккаунт:** `demo@nova.local` / `Demo2026!`. Есть кнопка быстрого входа.

```sh
npm run typecheck
npm test
npm run build
npm run preview
```

## Что работает

- Валидация входа, защищённые маршруты, выход; запоминание сессии в localStorage или sessionStorage.
- Обзор бизнеса, KPI и графики, сравнение периодов, задачи команды и события.
- Аналитика продаж: 7/30/90 дней, свой диапазон, каналы и лучшие товары.
- Заказы: поиск, комбинированные фильтры, сортировка, пагинация, безопасный экспорт CSV, создание и редактирование позиций, скидки, оплаты и доставки.
- Клиенты: контакты, сегменты, ответственные, связанные заказы и сделки, рассчитанные покупки.
- Воронка: 6 этапов, drag-and-drop на компьютере, доступное изменение этапа через select на всех устройствах, создание заказа из выигранной сделки без дублирования.
- Задачи: исполнитель, отдел, срок, приоритет, завершение и возобновление.
- Обзорные страницы отделов, сотрудники, демонстрационный каталог склада.
- Поиск по рабочему пространству (`Ctrl/Cmd + K`), уведомления и переходы к записям.
- Профиль, светлая/тёмная темы, сворачивание навигации, мобильное меню.
- Версионированное хранилище, проверка связей, уведомление об ошибках сохранения, восстановление демоданных с подтверждением.

## Сценарий демонстрации

1. Войти через демо-аккаунт, показать обзор и изменить период.
2. Открыть **Продажи → Клиенты** и добавить клиента.
3. В **Воронке** создать сделку с этим клиентом, товарами и ответственным.
4. Переместить сделку в «Выиграно», открыть её и нажать «Создать заказ».
5. Выбрать оплату «Оплачен», внести доставку и скидку, сохранить заказ.
6. Проверить обновление аналитики и карточку клиента; перезагрузить страницу, чтобы убедиться в сохранении данных.
7. Создать задачу, завершить её, открыть уведомления и переключить тему.

## Данные и расчёты

Демонабор: 24 товара, 60 клиентов, 240 заказов за 180 дней, 28 сделок, 7 сотрудников, 18 задач. Даты при первой загрузке привязаны к текущему дню по Москве. Восстановление создаёт свежий набор относительно дня сброса.

Суммы хранятся в копейках. Итог заказа = позиции − скидка + доставка. Выручка учитывает оплаченные неотменённые заказы; средний чек — выручку, делённую на их количество. Даты аналитики относятся к дате создания заказа. Конверсия — выигранные сделки среди закрытых сделок, созданных в выбранном периоде. Сравнение использует предшествующий период такой же длины. Топ товаров показывает продажи позиций до скидок и доставки. План выручки отмечен как демонстрационный.

### Финансы и раскрытие показателей

Карточки KPI открывают расшифровку за выбранный период с формулой, сравнением и связанными записями. График переключается между выручкой, валовой и операционной прибылью, операционными расходами. Раздел **Финансы** содержит отчёт о прибыли и расходах и редактор допущений.

Себестоимость — заданная доля стоимости товаров до скидки. Комиссии каналов рассчитываются со стоимости товаров после скидки, без доставки. Обработка и логистика задаются на оплаченный неотменённый заказ. Постоянные месячные бюджеты (ФОТ, аренда, маркетинг, сервисы) распределяются по календарным дням с сохранением копеек. Операционная прибыль = выручка − себестоимость − комиссии − обработка/логистика − постоянные расходы. Налоги, проценты и амортизация не включены. Все допущения являются демонстрационными, едиными для периодов и редактируются; это управленческая модель, а не бухгалтерский учёт.

Баннер и блок знакомства с NOVA скрываются крестиком, состояние сохраняется. Вернуть их можно в **Настройки → Внешний вид**. Исходный профиль — **Али Бабаев, руководитель компании**; старый исходный демо-профиль обновляется автоматически без сброса заказов и других данных.

## Архитектура

- `src/data/`: Zod-схемы, связанные демоданные, типизированные операции хранилища, расчёты и тесты.
- `src/components/`: оболочка, графики, диалоги сущностей и компоненты интерфейса.
- `src/pages/`: вход, обзор, продажи, отделы, задачи и настройки.

UI вызывает операции Zustand (`saveOrder`, `saveCustomer`, `saveDeal`, `convertDeal`, `saveTask`) вместо прямой записи в localStorage. При подключении backend эти операции можно заменить запросами, сохранив формы и представления.

## GitHub Pages

Репозиторий пока не подключён. После его создания:

1. Загрузить исходники вместе с `package-lock.json` и `.github/workflows/pages.yml` в ветку `main` или `master`.
2. В **Settings → Pages → Build and deployment** выбрать **GitHub Actions**.
3. Дождаться успешного workflow **Check and deploy NOVA ERP**. URL появится в environment `github-pages`.

Workflow выполняет проверку типов, тесты, сборку и публикацию; pull request проходит проверки без публикации. `base: './'` позволяет работать в подпапке репозитория, HashRouter поддерживает прямые ссылки и перезагрузку маршрутов без серверного fallback. Секреты для публикации не нужны: используется стандартный `GITHUB_TOKEN` с минимальными правами.

## Границы MVP

Это демонстрационный frontend. Авторизация не обеспечивает серверную защиту. Нет реальных платежей, отправки сообщений, маркетплейс-интеграций, складских проводок и синхронизации между пользователями. Показатели маркетинга и закупок, остатки и план выручки являются демонстрационными и явно подписаны.

Изменения хранятся только в браузере на конкретном origin: `localhost`, `127.0.0.1` и GitHub Pages имеют разные наборы данных. Очистка браузера удаляет изменения. Email в настройках меняет профиль, но не данные демовхода. Пароли не сохраняются. Данные для показа вымышленные.
